# 三点估算方案（PERT）

## 适用场景
适用于存在技术不确定性、需求模糊点、或涉及新技术/第三方对接的项目。通过量化风险区间来提高估算可信度，特别适合对外报价需要体现"保守/乐观"区间的场景。

## 核心原理

PERT（Program Evaluation and Review Technique）三点估算法：对每个不确定的估算，给出三个值，用加权公式计算期望值，以量化不确定性。

**期望人天 E = (O + 4M + P) / 6**

| 符号 | 含义 | 说明 |
|------|------|------|
| O | 最乐观（Optimistic） | 一切顺利、无阻碍、无需求变更的最短耗时 |
| M | 最可能（Most Likely） | 正常节奏、有常规沟通损耗、有小 bug 的常规耗时 |
| P | 最悲观（Pessimistic） | 遇到技术难点、需求歧义、第三方接口不稳定、关键人员请假 |

## 估算方法

### 第一步：三个场景假设（在脑中完成）
对每个叶子行和每个参与的工种，分别设想三种场景并给出估算：

**最乐观 (O)**：
- 需求理解完全无误
- 依赖方接口稳定可用
- 无技术难点，复用现有代码
- 一天都不加班，但也无阻塞
- 值应该偏低但合理，不是"理想化到不现实"

**最可能 (M)**：
- 有少量需求澄清来回
- 有 1-2 个小 bug 需要调试
- 有常规的会议和沟通打断
- 这是你最诚实的预估

**最悲观 (P)**：
- 需求有模糊点需要多轮沟通
- 遇到一个技术难点需要调研解决
- 第三方接口联调不顺
- 有代码评审意见需要返工
- 值应该偏高但不过分，是可发生的"倒霉情况"

### 第二步：计算期望值
公式：E = (O + 4M + P) / 6

示例（前端"多条件筛选搜索"）：
- O = 0.5 人天（一切顺利，组件库直接用）
- M = 1.0 人天（有筛选状态管理，需要调试）
- P = 2.0 人天（筛选条件多、交互复杂、联调出问题）
- E = (0.5 + 4×1.0 + 2.0) / 6 = 6.5/6 = 1.08 → 1.0 人天

示例（后端"用户权限校验"）：
- O = 0.5 人天（权限模型已有，纯配置）
- M = 1.0 人天（需要小幅调整权限逻辑）
- P = 2.5 人天（权限需求不明确，可能需要重新设计）
- E = (0.5 + 4×1.0 + 2.5) / 6 = 7.0/6 = 1.17 → 1.0 人天

### 第三步：四舍五入到 0.5 粒度
- 期望值 < 0.25 → 填 null 或 0
- 期望值 0.25-0.74 → 0.5 人天
- 期望值 0.75-1.24 → 1.0 人天
- 期望值 1.25-1.74 → 1.5 人天
- ...以此类推

### 第四步：不确定度标注
如果某个叶子的 (P - O) 差值很大（> 1.5 人天），说明不确定性高。在 remark 中简要标注原因。

## 何时使用三点估算 vs 直接给最可能值

**必须用三点估算**：
- 涉及新技术/新框架（团队没有经验积累）
- 需要对接第三方系统（依赖方不可控）
- description 中有"实时"、"高并发"、"大数据量"等性能敏感词
- 需求描述较模糊，有解释空间

**可以直接给最可能值**：
- 标准的 CRUD 页面功能
- 基于成熟组件库的 UI 开发
- description 清晰且无歧义
- 同类功能在项目中已多次出现（用前几个的 M 值作为当前 O 值）

## 各工种参考范围

**前端开发 (frontend)**
- 简单页面 O:0.3 M:0.5 P:1.0
- 中等交互 O:0.5 M:1.0 P:2.0
- 复杂功能 O:1.0 M:2.0 P:4.0
- design 行：填 null

**后端开发 (backend)**
- 简单 CRUD O:0.3 M:0.5 P:1.0
- 中等业务 O:0.5 M:1.5 P:3.0
- 复杂功能 O:1.5 M:3.0 P:5.0
- design 行 O:1.5 M:3.0 P:5.0

**UI设计 (design)**
- 组件库页面 O:0.3 M:0.5 P:1.0
- 自定义页面 O:0.5 M:1.5 P:2.5
- 设计体系 O:1.0 M:2.0 P:3.0

其他工种参照各自的常规范围给出三点值。

## 输出格式
只输出纯 JSON 数组，trades 字段已填充（填期望值 E，而非 O/M/P）。
O/M/P 的思考过程不要输出。

## 约束
- 最终 trades 值必须是 0.5 粒度的 E 值
- 已选工种全部填写，不参与的填 null
- design 行前端填 null
- 不确定性高的叶子在 remark 简要说明
- 总人天合理，期望值不应过分偏离最可能值
