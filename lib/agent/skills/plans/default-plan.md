# 默认工时估算方案

## 适用场景
通用软件项目开发（Web应用、管理系统、移动端等）

## 工时基准（人天 / 每功能项）

### 前端开发 (frontend)
| 复杂程度 | 人天 | 典型场景 |
|---------|------|---------|
| 简单 | 0.5 | 静态展示页、表单页面 |
| 中等 | 1-2 | 含图表/数据交互、列表筛选 |
| 复杂 | 2-4 | 实时数据大屏、复杂交互、自定义组件 |

### 后端开发 (backend)
| 复杂程度 | 人天 | 典型场景 |
|---------|------|---------|
| 简单 | 0.5-1 | CRUD单表API |
| 中等 | 1-3 | 多表关联、复杂业务逻辑、文件处理 |
| 复杂 | 3-5 | 实时数据处理、第三方集成、复杂权限 |

### UI设计 (design)
| 复杂程度 | 人天 | 典型场景 |
|---------|------|---------|
| 简单 | 0.5 | 基于组件库的标准页面 |
| 中等 | 1-2 | 需要自定义设计的关键页面 |
| 复杂 | 2-3 | 品牌定制、完整设计体系 |

### 测试 (testing)
- 按总开发工时的 15%-25% 估算
- 简单功能 0.5 人天起步

### 项目管理 (pm)
- 按总工时的 10% 估算
- 简单项目至少 1 人天

### DevOps (devops)
- 仅系统设计/部署相关功能涉及
- 1-3 人天

### 数据分析 (data)
- 仅数据建模/报表功能涉及
- 1-3 人天

### AI/算法 (ai)
- 仅涉及AI功能的项目
- 最少 2 人天起步

## 系统设计类 (category=design)
- 前端：通常不参与（填 null）
- 后端：2-5 人天（架构设计、技术选型）
- 设计：1-3 人天（UI设计体系）
- DevOps：1-2 人天（部署架构）
- 数据：1-3 人天（数据建模）

## 估算约束
- 人天粒度：0.5 人天
- 已选工种全部填写，不参与该功能的填 null
- 总人天应合理，避免过度估算
